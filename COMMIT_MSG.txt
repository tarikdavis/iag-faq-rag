Synthesize question variants for non-FAQ content at index-build time

Diagnosis: inspiration sections + banners were getting out-ranked by FAQ
chunks even when more on-topic, because FAQs have tight question-shaped
retrieval headers (question + variants + searchSummary) while non-FAQ
content embedded as 'heading + long content body' produced smeared
vectors. A query like 'can i fly to new york' couldn't lock onto the
'Heathrow to New York' inspiration section, even though the heading
contains both proper nouns.

Fix: synthesize 4 search-shaped question variants per non-FAQ entry
using Haiku at index-build time. Variants get prepended to the
retrieval_header alongside heading + truncated content snippet, giving
the embedder multiple intent-shaped signals to match against. Mirrors
the FAQ retrieval shape so the whole corpus is consistent.

New module:
- src/synthesize_variants.py — handles cache + Claude call. Cache
  keyed by (entry_id, locale) with content-hash invalidation; bump
  PROMPT_VERSION to invalidate everything in one go. Silent fallback
  to empty list if Claude is unreachable so the build never crashes.

Modified:
- src/load_faqs.py — both inspiration + banner loaders now call
  get_variants() and build retrieval_header as
  heading + variants + ~120-word content snippet.

Cache committed:
- data/retrieval_variants_cache.json — Render redeploys read the
  committed cache and pay zero Claude cost. Only new/edited content
  triggers a synthesis pass.
